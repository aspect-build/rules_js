# Yarn PnP zero-install e2e

A minimal [Yarn zero-install](https://yarnpkg.com/features/caching#zero-installs)
project consumed by Bazel without ever running Yarn.

The checked-in artifacts were generated with `yarn install` (Yarn 4.18.0,
`pnpEnableInlining: false`, `enableGlobalCache: false`) and are consumed
as-is:

-   `yarn.lock` — resolution graph with per-archive sha512 checksums
-   `.pnp.data.json` — the complete package registry: every locator, its
    location in the offline cache, and its dependency edges
-   `.pnp.cjs` — the PnP resolver loaded into node via `--require`
-   `.yarn/cache/*.zip` — the offline package archives
-   `.yarn/unplugged/**` — checked-in content Yarn intentionally loads outside
    cache zips (`left-pad` is forced unplugged to exercise this real format)
-   `.yarnrc.yml` — the PnP configuration used to generate the graph
-   `.pnp.integrity.json` — sha512, regular-file type, and executable-mode
    binding for the resolver, graph, config, lockfile, cache, and unplugged files

`@pnp//:defs.bzl` is generated by the `pnp` module extension, which validates
lock-declared edges plus root/fallback references, verifies the explicit
integrity manifest, and exposes
`pnp_js_binary` / `pnp_js_test` / `pnp_verify_test`. All resolution and
node_modules-topology decisions were made by Yarn on the developer's machine.
rules_js does not synthesize a node_modules tree, but the importer deliberately
recognizes Yarn's generated cache, virtual-cache, and unplugged path forms.

This fixture covers Yarn 4.18 lockfile metadata v10, a physical SOFT package
with a virtual HARD peer instance (`react-dom`), and a HARD unplugged package.

To update dependencies, edit `package.json`, run `yarn install`, regenerate the
integrity manifest, and commit all changed artifacts:

```sh
bazel run @aspect_rules_js//npm/private/pnp:pnp_integrity -- \
  --root "$PWD" --output "$PWD/.pnp.integrity.json"
```

The generator rejects source symlinks and empty unplugged directories because
Bazel filegroups cannot preserve those semantics reliably. Add a checked-in
marker file to any required empty directory before regenerating the manifest.
