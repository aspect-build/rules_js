# Yarn PnP zero-install e2e

A minimal [Yarn zero-install](https://yarnpkg.com/features/caching#zero-installs)
project consumed by Bazel without ever running Yarn.

The checked-in artifacts were generated with `yarn install` (Yarn 4.12.0,
`pnpEnableInlining: false`, `enableGlobalCache: false`) and are consumed
as-is:

- `yarn.lock` — resolution graph with per-archive sha512 checksums
- `.pnp.data.json` — the complete package registry: every locator, its
  location in the offline cache, and its dependency edges
- `.pnp.cjs` — the PnP resolver loaded into node via `--require`
- `.yarn/cache/*.zip` — the offline package archives

`@pnp//:defs.bzl` is generated by the `pnp` module extension, which
cross-validates `.pnp.data.json` against `yarn.lock` and exposes
`pnp_js_binary` / `pnp_js_test` / `pnp_verify_test`. All resolution and
layout decisions were made by Yarn on the developer's machine and are fully
described by the checked-in files; rules_js only consumes them.

To update dependencies, edit `package.json`, run `yarn install`, and commit
the regenerated artifacts — the same review model as `pnpm-lock.yaml`.
